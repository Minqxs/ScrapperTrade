# Research Improvement Loop

- Trigger: schedule or performance envelope event. Objective: generate constrained, attributable challengers off the hot path.
- Agents: AI/Knowledge, Quant, Reviewer, Learning Curator.
- States: SELECT EVIDENCE -> VERIFY PROVENANCE -> HYPOTHESIS -> STRATEGY SPEC -> VALIDATE -> CHALLENGER -> SHADOW -> COMPARE -> RECOMMEND/REJECT.
- Gates: source provenance, ambiguity/conflict recording, schema validity, validation-loop pass, no leakage, champion remains unchanged without promotion authority.
- Retry/stop: failed hypotheses are retained, not silently retuned; diagnose recurring data/assumption faults. Stop on evidence-backed verdict or resource limit.
- Permissions/boundaries: AI cannot execute, alter hard policy, allow instruments, unlock emergency mode, or self-promote. Paid APIs and large jobs need user authorization/resource policy.
